## 1. 测试对象与实施原则（システム試験方針）

- 面向**完整已安装产品**的系统试验，覆盖 Windows 11 x64、中文/英文/日文语言 Profile、七种编程语言、VS Code 全文 Bridge、普通文本宿主的降级、AI/隐私、F1 编辑、安装迁移和性能。
- 把真实系统级输入能力与“普通应用可取得全文”区分验证：VS Code 作为 P0 FullFile 宿主，其它宿主在无 Bridge 时只验收 Direct 与合法局部输入，不能因为缺全文就假装通过全文编辑。
- 推荐 OS 环境矩阵：Win11 x64 两个受支持 Build，语言 zh-CN/en-US/ja-JP，DPI 100/150/200/250%，单/双显示器；应用 Notepad、VS Code 必测；Visual Studio、JetBrains、Terminal、浏览器为兼容分级报告（Direct 可用/受限/不支持），不得将超出产品承诺的全文能力算作失败或暗中承诺。
- 正式 P95 性能用受控基准机 1000 条输入事件计算；AI 延迟与本地调度延迟分别计量；高风险/人工可访问性场景保留实机证据。
- 准入：UT/IT P0 通过、G0/G1 原型证据通过、签名测试版安装成功；退出：全部 P0 ST 通过、严重安全/源码覆盖/原输入法损坏问题=0。

| Fixture ID | 数据说明 | 关键断言 |
|---|---|---|
| FX-LANG-01 | 七种语言有效/无效语法文件 | grammar/dialect/validator 返回可复核 |
| FX-UTF16-01 | `A😀B`、CJK、CRLF/LF、尾随换行 | 不拆代理项、不漂移范围 |
| FX-DIRTY-01 | 编辑器 v42 原文与 v43 未保存 buffer | 实际使用最新 buffer 生成基线 |
| FX-AI-01 | 确定性 Fake Provider: 正常、401/429、错序、无效 JSON、恶意 toolcall | 请求次数/结果语义严格断言 |
| FX-SECRET-01 | 完全虚构的 Key、`.env` 与 PRIVATE KEY 头 | 零泄露/明确阻断或脱敏 |
| FX-EDIT-01 | 两个不重叠 Hunk、两个重叠 Hunk、旧版 Apply token | 正确预览、冲突拒绝、零多余写入 |
| FX-ASM-01 | 已独立核验 x86-64 指令与预期字节、未解析标签 | 合法可验证/不确定不可验证 |
| FX-OS-01 | 受控 Windows 11 VM，安装三语言配置及原输入法 | 可重复恢复的安装/卸载基线 |

**Fixture 管理：** 每组保存 `fixture_id, schema_version, source, sha256, expected_output`；真实用户的 API Key、文件与聊天内容不得作为测试数据。涉及系统测试时另记录 OS Build、用户会话、输入语言、显示器布局、编辑器和扩展版本。

## 4. 执行记录与缺陷处理（実施記録・不具合管理）

用例执行时记录：`test_id`、环境 ID、构建 Commit/hash、Fixture SHA-256、开始/结束时间、操作者、自动化 job、预期与实际、截图/日志路径、缺陷单号与复测状态。所有未执行项保持 `Not Run`，不得默认视为 `Pass`。

- 判定：`Pass`（全部期待成立）、`Fail`（任一关键断言失败）、`Blocked`（环境/前置条件缺失）、`Not Run`、`Not Applicable`（须写批准理由）。
- 对关键问题使用 `Stop Ship`：文件内容非授权修改、Key/源码外泄、密码框上传、重复编辑、原始输入丢字或原系统输入法遭损坏。
- P0 通过率计算时**Blocked/Not Run 不计 Pass**；只有在对应环境完成全部 P0 后才能签署相应测试层级。
- 功能追踪用 Excel 的 `Requirements` 与 `{level}_Cases` 工作表；变更要求必须同步更新受影响 DD/测试和期待结果。

## 5. 设计审查清单（レビュー項目）

1. 每条用例是否具备稳定的前提、操作、输入数据、可断言的预期结果和证据路径？
2. 是否包含正常、异常、边界、安全、并发/超时或退化路径，而不是只测试成功路径？
3. 测试层级是否正确：UT 针对算法，IT 针对接口，ST 针对系统与用户场景？
4. 需要真实 Windows/Provider/编辑器的部分是否明确标出，未把 Mock 通过冒充实测？
5. 所有涉及文件修改/外送的场景，是否确认未授权时零写入、零外发及可恢复？
