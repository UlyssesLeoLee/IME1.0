## 2026-11-02 第三、四轮改动（本轮）

1. **改名**：产品名 IME1.0、描述「编程输入法」（COM 类名、三个语言 profile、ARP 名称与 Comments、安装器三语文案、UI element 描述、文档）。
2. **F1/F2 冲突**：VS Code 扩展里的 F1/F2（与编辑器的「帮助」「重命名符号」冲突）改为 **Ctrl+F1 / Ctrl+Shift+F1 / Ctrl+F2 / Ctrl+Shift+F2**；配置项 `programmingIme.f1Binding` / `f2Binding` 的枚举与默认值同步更新。
3. **记事本里候选窗不出现 / 选不了（根因已定位并修复）**：新记事本是 WinUI 应用，`Windows.UI.Xaml.dll` 实现了 `ITfUIElementSink`，会把候选列表**接管过去自己画**。我们此前只在 `BeginUIElement` 里发布列表、却**没有按协议发一次带全部标志位的 `UpdateUIElement`**（微软的规则：宿主在第一次 Update 时才读内容，且标志位必须齐全），宿主因此没有任何内容可画；而且我们**没有实现 `ITfCandidateListUIElementBehavior`**，宿主即使画出来了也无法把用户的选择告诉输入法。现在两处都补齐：`BeginUIElement` 返回「宿主自己画」后立刻补发一次全标志位的更新；行为接口的 `SetSelection` / `Finalize` / `Abort` 通过一条新的动作通道回到 controller。
4. **鼠标点选**：原生候选窗原来**完全没有鼠标处理**（只有 WM_MOUSEACTIVATE / WM_PAINT），现在点击某一行 = 选中并上屏该行（与按数字键等价），窗口仍不抢焦点。
5. **Tab 与数字键**：**候选窗在屏幕上时，Tab 属于候选窗**——按 Tab **确认高亮候选并上屏**（主流输入法行为，Shift+Tab 往回走）；数字键 1–9 仍然按传统输入法的方式直接选中并上屏。两个开关：`tab_cycles`（勾上＝Tab 只在候选间移动，程序员习惯）与 `tabToHost`（勾上＝Tab **完全交还给宿主**，IDE 保留缩进，候选窗退化成纯预览）。**默认两个都不勾**，也就是「按 Tab 就上屏」。
6. **输入模式（Alt+F1）**：默认仍是「直接模式」（一个代码字符都不吞）；按 **Alt+F1** 进入「输入模式」，此时行为与微软输入法一致：打字自动开组合、候选窗可交互、数字键/Tab/回车/空格都能用。输入模式是**每个语言各自**的状态（中文、日文各管各的），设置界面与悬浮窗按钮是同一个入口。
7. **悬浮窗（搜狗拼音式工具条）**：光标旁常驻一条小工具条，六个按钮：`中/英`（直接模式 ↔ 输入模式）、`AI`（effort 菜单）、`外观`（皮肤菜单：跟随系统 / 浅色 / 深色）、`便捷`（编程常用开关：**Tab 确认候选上屏**、**候选窗显示时 Tab 交给宿主**、空格上屏、自动开组合、显示悬浮窗）、当前语言（**可搜索的下拉菜单**，可向上弹出）、`设置`（设置窗口）。工具条不抢焦点（`WS_EX_NOACTIVATE`），点它不会让编辑器失焦。
8. **设置界面**：从悬浮窗的「设置」打开，按语言分组（中文 / English / 日本語），每组：候选页大小 1–9、**Tab 确认候选上屏（不勾＝Tab 只移动选择）**、**候选窗显示时 Tab 交给宿主（IDE 保留缩进）**、空格上屏、自动开组合、默认进入输入模式、显示悬浮窗。设置写在 `%LOCALAPPDATA%\Programming IME\settings.json`（原子写入，文件坏了就用默认值，不影响输入法启动）。
9. **语言切换**：悬浮窗的语言按钮打开**带搜索框**的下拉菜单（可向上弹出），选中后调用 TSF 的 `ActivateLanguageProfile` 切换当前 profile；AI effort 与外观皮肤是全局设置，随同一个文件保存。

## 2026-11-03 第十轮改动（本轮：候选选择修复 + 语音输入 + 常驻与一键切换）

### 一、你报的缺陷：候选选不了（已修）

**现象**：候选列表出来后，上下键走不了，Tab / 空格 / 回车都取不到内容。

**根因**：不是按键处理坏了，是**出厂默认是「直打模式」**——该模式下上下键不在保留键集合里、空格与回车按设计就交给宿主。实测：直打模式 `up/space/enter` 全部不消费；输入模式下四个键全部消费且成功上屏。

**处置**：把出厂默认改成**输入模式**（主流输入法行为），空格改为默认确认候选；直打模式保留，Alt+F1 / 悬浮栏可切回。新增回归测试 `tests/tsf/ime_selection.rs`（4 个用例）把四个键钉住。

### 二、新功能

## 2026-11-05 第十七轮改动（本轮：给主流 AI 开放输入法的接口——MCP + CLI + 本地管道/HTTP + 真写入通道）

这一轮接的是你点的要求：**「你要开放足够的接口给各种主流 ai，让它们可以调用输入法书写代码，节省 token」**。

你的三个决定：**写入目标是焦点窗口的光标处**（真 TSF 上下文）；**MCP(stdio) + CLI + 本地命名管道/HTTP 三件套全要**；**独立客户端通用接入 + 文档**（VS Code 扩展侧本轮不做）。

### 一、为什么需要这一层

输入法是**装在每一个应用里的 TSF 文本服务**：只有它知道当前文档、光标和选区。一个跑在别处的 AI（一个 MCP 客户端、一个 CLI、一个脚本）**没法自己往那个文档里写字**——它得请焦点窗口里的输入法替它写，并且知道写没写成。

```
AI 客户端 ──MCP/CLI/HTTP──▶ pime-mcp / pime-ime ──WM_COPYDATA──▶ 焦点窗口里的 pime_tsf.dll ──▶ 文档
```

**省 token 的地方**：AI 不用再逐字符模拟按键（一次调用写一整段，中文/日文一次到位，不用组字、不用选词、不用按坐标点），也不用把长文本拆成几十次工具调用。

### 二、做出来的东西

1. **一份线上契约**（`crates/pime-core/src/agent_proto.rs`，新）：请求 / 回答 / 6 个操作（写入、读选区、切语言、状态、没找到的词、整理词库）/ 8 个错误码 / 载荷上限 1 MiB / 两个消息码 / 窗口类名与标题前缀。**两侧共用这一份**，协议不会漂移（10 项往返单测）。
2. **DLL 侧的桥接窗口**（`crates/pime-tsf/src/agent_bridge.rs`，新）：输入法激活时开一个隐藏顶层窗（类 `PIME1AgentBridge`、标题 `PIME1.<nonce>`），用 `WM_COPYDATA` 收请求、用 `SendMessageW` 回答案。**消息结构体本地声明**（24 字节，偏移 0/8/16，有单测钉住）——没有给 `windows` crate 加 feature（会整包重编并 OOM）。

### 三、这一轮抓到的真缺陷（已修，请你追认或让我回退）

7. **桥接窗口只能开一次**：切走再切回来，AI 就再也叫不动输入法了。真因是「窗口类是否注册成功」记在了**局部变量**里，而 `Once` 的闭包**只在第一次执行** ⇒ 第二次调用永远拿到「没注册」。TSF 每次切输入法都会「停用→激活」，所以**第二次切换之后这条功能就废了**。已改成 `OnceLock` 并补了回归测试。
