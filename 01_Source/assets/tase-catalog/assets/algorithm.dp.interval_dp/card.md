# 区间动态规划（Interval Dynamic Programming）

- 资产 ID：`algorithm.dp.interval_dp`
- 类型：`algorithm`（算法）
- 分类：`dp`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`interval_dp`、`区间DP`、`矩阵链乘法`、`区间调度`

## 一句话定位

用"区间长度"作递推顺序：先算小区间，再算大区间，每个区间枚举分割点取最优。

矩阵链乘法、括号匹配、区间合并代价最小时，直接枚举所有方案是阶乘级的。

## 典型源文件形状

```text
interval_dp(cost):                   // cost[i][j] = 合并 i..j 的代价
    n = len(cost)
    dp = matrix of size n x n filled with INF
    for i in 0..n: dp[i][i] = 0
    for length in 2..=n:              // 按区间长度递推
        for i in 0..=n-length:
            j = i + length - 1
            for k in i..j-1:          // 枚举分割点
                cand = dp[i][k] + dp[k+1][j] + cost(i, j)
                if cand < dp[i][j]: dp[i][j] = cand
    return dp[0][n-1]
```

## 适用条件

- 问题天然按区间划分（合并成本依赖区间跨度）
- 最优解具有"最后一次分割"的结构
- 需要还原分割方案（记 traceback）
- n 在几百量级

## 反例

- 问题没有区间结构——强行套用只会增加维度
- 存在贪心解且可证明——优先贪心（区间调度经典贪心）
- n 较大——O(n³) 不可行
- 区间划分方式不唯一且需要枚举多种——状态定义会爆炸

## 并发风险

- DP 纯计算，无共享状态
- 按区间长度递推天然有层间依赖；同一长度内的区间彼此独立，可以并行
- 只读代价矩阵共享安全
- 并行化收益取决于每层的并行宽度

## 替代方案

- `algorithm.dp.bitmask_dp` — 状态维度是"集合的位掩码"时用位掩码 DP。
- `algorithm.dp.longest_common_subsequence` — LCS 是按行列推进的二维 DP，与区间 DP 同属"按子问题规模递推"的家族。

## 测试说明

- 与暴力枚举所有分割方案（小 n）交叉比较
- n = 1（不分割）、n = 2
- 代价矩阵不满足三角不等式等结构性假设（算法不应依赖额外假设）
- 还原的分割方案确实能凑出 DP 值
- 非对称代价（cost(i,j) ≠ cost(j,i)）
- 随机小规模的性能回归

## 实现注意

- 优先标准库/成熟库：没有标准库实现；这类问题通常直接按题目定制实现
- 复杂度：典型时间 O(n³)，额外空间 O(n²)；具体取决于状态数与转移数
- 稳定性：不适用
- 内存：O(n²) 矩阵；n = 2000 时 `u64` 矩阵约 32 MB，n = 10000 时不可行
- 溢出：代价与 dp 值要用 `i64`/`u64`；INF 参与加法必须先判 INF
- 极端输入：n = 1、完全不平衡的代价、极大代价值
- 并发安全：纯计算；同层区间可并行
- 限制：O(n³) 时间与 O(n²) 空间；状态定义不当时维度爆炸
