# 最长公共子序列（Longest Common Subsequence）

- 资产 ID：`algorithm.dp.longest_common_subsequence`
- 类型：`algorithm`（算法）
- 分类：`dp`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`longest_common_subsequence`、`LCS`、`最长公共子序列`

## 一句话定位

二维 DP 表：若两端字符相同就沿对角线 +1，否则取"跳过 a"和"跳过 b"两者的较大值。

对比两段文本的相似内容、找两个版本的共同段落、变更检测，都需要公共子序列。

## 典型源文件形状

```text
lcs_length(a, b):
    m = len(a); n = len(b)
    prev = array of size n+1 filled with 0
    for i in 1..=m:
        cur = array of size n+1
        for j in 1..=n:
            if a[i-1] == b[j-1]: cur[j] = prev[j-1] + 1
            else: cur[j] = max(prev[j], cur[j-1])
        prev = cur
    return prev[n]
```

## 适用条件

- 需要比较两个序列的公共内容
- 序列长度中等（几百到几千）
- 需要具体公共子序列而不只是长度
- 变体：最长公共子串（要求连续）也基于同一 DP 框架

## 反例

- 只需要子序列判定——双指针更简单更快
- 序列很长——O(n·m) 代价过高
- 字符集大且关心相似度——编辑距离的度量更适合
- 需要处理大量两两比较——可先按长度/哈希粗筛

## 并发风险

- 纯计算，无共享状态
- 并行化需要按对角线分块（同一对角线上的格子互不依赖），比按行分块更自然
- 只读输入共享安全
- 滚动数组版本无法直接并行（行间有依赖），需要保留完整矩阵才能并行

## 替代方案

- `algorithm.dp.longest_increasing_subsequence` — LIS 只涉及单个序列，LCS 涉及两个序列的对齐。
- `algorithm.string.edit_distance` — 编辑距离与 LCS 都是对齐类 DP，但代价函数与度量目标不同。

## 测试说明

- 与完整矩阵实现交叉比较
- 空序列、单元素、两个相同序列、完全不同的序列
- 含重复元素
- 对称性：断言 lcs(a,b) == lcs(b,a)
- 子序列性质：还原出的公共子序列必须是两者的子序列
- Unicode（按 char 比较）

## 实现注意

- 优先标准库/成熟库：没有标准库 LCS；成熟 crate 有 `lcs` 等，引入前需核查许可
- 复杂度：时间 O(n·m)，额外空间 O(min(n,m))（滚动数组）；需要还原路径时用 O(n·m) 矩阵
- 稳定性：不适用
- 内存：O(n·m) 矩阵在长序列上不可行（10000×10000 ≈ 800 MB）
- 溢出：长度用 `usize`；`prev[j-1] + 1` 需检查边界
- 极端输入：空串、单元素、完全相同、完全不重叠、Unicode 组合字符
- 并发安全：纯计算；完整矩阵版本可按对角线并行
- 限制：O(n·m) 时间与空间；不处理语义相似
