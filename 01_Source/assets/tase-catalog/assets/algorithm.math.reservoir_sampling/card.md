# 蓄水池抽样（Reservoir Sampling）

- 资产 ID：`algorithm.math.reservoir_sampling`
- 类型：`algorithm`（算法）
- 分类：`math`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`reservoir_sampling`、`蓄水池抽样`、`水塘抽样`、`reservoir`

## 一句话定位

维持一个 k 大小的"水塘"，每来一个新元素就以 k/i 的概率把它挤进池塘并随机踢出一个。

要从一个十亿条记录的日志里均匀抽样 1000 条做分析，但不知道有多少条，也不能全量载入内存。

## 典型源文件形状

```text
reservoir_sample(stream, k):
    reservoir = first k items of stream
    for i in k..:                      // i 为已看到的元素个数（0 基）
        j = random(0..=i)             // 均匀选一个位置
        if j < k: reservoir[j] = stream[i]
    return reservoir
```

## 适用条件

- 流式数据、总长度未知
- 只能单遍扫描、内存受限
- 需要均匀（等概率）抽样
- 样本量 k 相对总数据量很小

## 反例

- 已知总数——直接随机选下标更简单
- 可以两遍扫描——第一遍计数，第二遍按概率抽样
- 需要加权抽样——等概率蓄水池不适用
- 需要按时间分段抽样——应使用分层抽样

## 并发风险

- 单遍算法天然适合流式，但并行化需要"按分区各抽样 + 按分区大小加权合并"
- 合并公式：两个分区各抽 k 个，按分区规模加权合并后再抽 k 个
- 共享 RNG 需要线程安全（`rand` 的 `thread_rng` 是每线程的），或用显式种子保证可复现
- 随机源的熵获取在受限环境下可能失败——要有确定的退化策略

## 替代方案

- `algorithm.sorting.top_k_heap` — 若需要的是"最 k 大"而非随机样本，用堆更合适。
- `algorithm.datastructure.binary_heap` — 最小堆变体可实现 O(n log k) 的蓄水池，需要额外的堆操作。

## 测试说明

- 小数据集下统计每个元素被选中的频率，断言接近均匀
- k = 0（返回空）、k = 1、k = n（返回全部）
- 流长度小于 k（返回全部）
- 多次运行的结果不总相同（随机性生效）
- 固定随机种子时结果可复现（若实现支持）
- 并行分片合并后的分布与串行一致

## 实现注意

- 优先标准库/成熟库：Rust 标准库没有蓄水池抽样；成熟 crate 有 `rand::seq::index::sample`（需 `rand` 依赖），引入前需核查许可
- 复杂度：时间 O(n) 总摊还（每元素一次随机数与常数次操作），空间 O(k)
- 稳定性：不适用
- 内存：O(k)，与总数据量无关
- 溢出：`i` 计数与随机索引要用 `usize`；k 与 n 的比较要避免类型不匹配
- 极端输入：空流、k 大于流长度、单元素流、极大 k
- 并发安全：单遍本地计算安全；并行合并需要按分区大小加权
- 限制：只做等概率抽样；不支持加权或分层；需要可用的随机源
