# Z 算法（Z Algorithm）

- 资产 ID：`algorithm.string.z_algorithm`
- 类型：`algorithm`（算法）
- 分类：`string`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`z_algorithm`、`Z算法`、`Z-function`、`扩展KMP`

## 一句话定位

为字符串的每个后缀求出它与整个字符串的最长公共前缀，一次扫描完成。

需要知道"以每个位置开头能匹配多长的模式"，以及拼接前后缀是否相等（字符串哈希、周期分析）。

## 典型源文件形状

```text
z_function(s):
    z = array of size n; z[0] = n
    l = 0; r = 0                      // 当前最靠右的匹配区间 [l, r)
    for i in 1..n:
        if i < r: z[i] = min(r - i, z[i - l])
        while i + z[i] < n and s[z[i]] == s[i + z[i]]: z[i] += 1
        if i + z[i] > r: l = i; r = i + z[i]
    return z
```

## 适用条件

- 计算所有后缀与整串的最长公共前缀
- 基于"模式 + 分隔符 + 文本"的一次性多模式匹配
- 字符串周期性与最小循环节分析
- 需要判断某两段是否以某种方式交错

## 反例

- 只需要单个模式的匹配位置——KMP 的实现与心智负担都更小
- 字符串极短——朴素比较足够
- 需要在线（流式、不可回看）——Z 函数需要整体预处理
- 需要匹配大量模式——Aho-Corasick 更合适

## 并发风险

- Z 函数是只读计算，结果数组可安全共享
- 多个不同字符串的 Z 函数计算可并行，互不干扰
- 若把 z 数组缓存在全局结构中，更新需要同步
- 无内部共享可变状态，天然可重入

## 替代方案

- `algorithm.string.kmp` — KMP 与 Z 算法几乎同构，前缀函数 vs Z 数组只是换了一种视角。
- `algorithm.string.aho_corasick` — 多模式同时匹配用 Aho-Corasick。

## 测试说明

- 断言 z[0] = n，其余位置与暴力计算一致
- 空字符串、单字符、全相同字符、无重复字符
- 周期串（如 "ababab"）与随机串
- 与 KMP 在"模式+分隔符+文本"构造上交叉比较匹配位置
- 边界：i 恰好等于 r 时的行为

## 实现注意

- 优先标准库/成熟库：Rust 标准库没有 Z 函数；如确需自写，注意下标边界
- 复杂度：时间 O(n)，额外空间 O(n)（z 数组）
- 稳定性：不适用
- 内存：O(n)，与输入等长；超大字符串需评估
- 溢出：下标用 `usize`；`i + z[i]` 可能溢出，实际不会超 n 但写法上仍应避免无界加法
- 极端输入：空串、单字符、全同、随机串、长周期串
- 并发安全：纯函数式计算，天然线程安全
- 限制：需要整体字符串在内存中；不能在线增量处理
