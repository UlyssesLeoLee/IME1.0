# 位掩码动态规划（Bitmask DP (Subset DP)）

- 资产 ID：`algorithm.dp.bitmask_dp`
- 类型：`algorithm`（算法）
- 分类：`dp`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`bitmask_dp`、`位掩码DP`、`状压DP`、`subset dp`

## 一句话定位

把"选过哪些元素"这个组合状态压进一个整数的二进制位，于是状态总数从 n! 降到 2^n。

"从 20 个城市里选若干个组成最短回路"若暴力枚举所有排列是 20!，用位掩码 DP 则是 2^20。

## 典型源文件形状

```text
tsp_held_karp(dist, n):              // dist[i][j] 为两点距离
    INF = huge
    dp = array of size 2^n filled with INF
    dp[1] = 0                          // 从点 0 出发，mask 只含点 0
    for mask in 1..2^n:
        if not visited_all(mask): continue
        last = highest_set_bit(mask)  // 最后一个到达的点
        for next in 0..n not in mask:
            new_mask = mask | (1 << next)
            dp[new_mask] = min(dp[new_mask], dp[mask] + dist[last][next])
    return min over masks of dp[mask] + dist[last][0]
```

## 适用条件

- 元素数少（通常 n ≤ 20）且子集状态是核心
- 旅行商、集合覆盖、分配问题的精确解
- 状态必须同时记录"选了什么"与"当前在哪"
- 需要精确最优解而非近似

## 反例

- n 较大——2^n 空间爆炸（n = 30 时约 10^9 项）
- 存在多项式或贪心解——状压是最"笨"但稳妥的精确解法
- 状态不涉及子集——用普通 DP 即可
- 需要多次不同初始集合的查询——每次都要重算表

## 并发风险

- DP 表是纯计算，可安全并行（按 mask 的高位分块，注意状态依赖方向）
- 2^n 的表本身极大，通常单线程更现实
- 只读输入（距离矩阵）共享安全
- 若用 `HashMap` 稀疏存状态以省内存，则不再是数组式并行，且哈希访问有额外开销

## 替代方案

- `algorithm.dp.interval_dp` — 状态是"区间"时用区间 DP，状态是"任意子集"时用位掩码 DP。
- `algorithm.datastructure.binary_heap` — 若只需要近似解（如贪心 + 局部搜索），堆能给出更快的结果。

## 测试说明

- 与暴力枚举（小 n，如 n ≤ 10）交叉比较
- n = 1、n = 2（边界）
- 图不连通：断言不可达状态为 INF
- 对称与非对称距离矩阵
- 断言还原的路径确实访问了每个点恰好一次
- n = 20 时的内存与时间回归（防止无意中使用 2^n 的哈希表撑爆内存）

## 实现注意

- 优先标准库/成熟库：没有标准库实现；成熟 crate 有 `bitmask` 之类，引入前需核查许可
- 复杂度：典型时间 O(2^n · n²)，额外空间 O(2^n)；n = 20 时表约 100 万项
- 稳定性：不适用
- 内存：2^n 项；n = 24 时 `u64` 表约 128 MB，n = 26 约 512 MB 已不可接受
- 溢出：掩码用 `u32`（n ≤ 32）或 `u64`（n ≤ 64）；`1 << n` 在 n = 32 时要防溢出与移位越界
- 极端输入：n = 0、n = 1、不连通图、极大距离值
- 并发安全：纯计算；表很大时并行收益有限
- 限制：只适用于 n 较小（≲ 20-24）；是精确但指数级的解法
