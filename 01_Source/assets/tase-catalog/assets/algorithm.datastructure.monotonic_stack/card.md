# 单调栈（Monotonic Stack）

- 资产 ID：`algorithm.datastructure.monotonic_stack`
- 类型：`algorithm`（算法）
- 分类：`datastructure`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`monotonic_stack`、`单调栈`、`monotonic deque`、`单调队列`

## 一句话定位

维护一个单调的栈或队列，每个元素最多进出一次，于是所有"下一个更大"类问题可以一次扫描解决。

求"每个元素右边第一个比它大的元素"，暴力是 O(n²)，用单调栈可以做到 O(n)。

## 典型源文件形状

```rust
pub fn next_greater(a: &[i64]) -> Vec<Option<usize>> {
    let mut ans: Vec<Option<usize>> = vec![None; a.len()];
    let mut stack: Vec<usize> = Vec::new();      // 栈内下标对应的值单调递减
    for (i, &x) in a.iter().enumerate() {
        while let Some(&top) = stack.last() {
            if a[top] < x {
                ans[top] = Some(i);
                stack.pop();
            } else { break; }
        }
        stack.push(i);
    }
    ans
}
```

## 适用条件

- 求每个元素的前一个/后一个更大或更小元素
- 接雨水、柱状图最大矩形、滑动窗口最值
- 需要在线处理流式数据（可用单调队列）
- 需要 O(n) 而非 O(n log n) 的"邻近更大"类问题

## 反例

- 只需要全局最值——直接扫描
- 需要频繁删除任意元素——单调结构的维护规则会复杂化
- 需要按值而非按下标比较——注意相等元素的处理口径
- 数据量小——暴力足够

## 并发风险

- 单调栈/队列是每次请求局部构造的，不共享时天然线程安全
- 在流式服务中若把单调队列放在共享结构里，需要锁或每连接一份
- 每连接（每线程）一份单调队列通常是最简单且最快的做法
- 队列实现要注意"队首过期"的条件与窗口定义一致

## 替代方案

- `algorithm.searching.sliding_window` — 滑动窗口是框架，单调结构常是其内部实现（窗口最值）。
- `algorithm.datastructure.binary_heap` — 堆能求前 k 大，但求"下一个更大"时堆需要额外处理且更慢。

## 测试说明

- 与暴力解法交叉比较
- 单调递增、单调递减、全相等、全不同
- 空数组、单元素
- 边界：找不到答案的元素应为 None
- 相等元素的口径（严格大于 vs 大于等于）要与文档一致
- 流式场景：滑动窗口最大值的过期条件测试

## 实现注意

- 优先标准库/成熟库：没有标准库实现；这类结构通常几十行内自写更清晰
- 复杂度：时间 O(n) 总摊还（每个元素最多入栈一次、出栈一次），空间 O(n)
- 稳定性：不适用
- 内存：O(n)；最坏情况（输入有序）栈深度达到 n
- 溢出：比较用 `Ord`；浮点数含 NaN 时单调性不成立，需特殊处理
- 极端输入：空数组、全相等、严格递增/递减（栈深 n）、含 NaN 的浮点数组
- 并发安全：局部构造则安全；共享则需同步
- 限制：只解决"邻近且单调"类问题；相等元素的口径必须明确
