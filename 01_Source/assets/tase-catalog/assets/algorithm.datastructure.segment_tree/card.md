# 线段树（Segment Tree）

- 资产 ID：`algorithm.datastructure.segment_tree`
- 类型：`algorithm`（算法）
- 分类：`datastructure`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`segment_tree`、`线段树`、`区间树`、`segment tree`

## 一句话定位

把数组按区间二分建成树，每个节点存自己区间的聚合值，于是区间查询只需合并 O(log n) 个节点。

数组频繁单点修改、同时要频繁查询任意区间和，普通前缀和数组要么修改 O(n) 要么查询 O(n)。

## 典型源文件形状

```rust
pub struct SegmentTree { tree: Vec<i64>, lazy: Vec<i64>, n: usize }

impl SegmentTree {
    pub fn query(&self, l: usize, r: usize) -> i64 {
        self.query_rec(1, 0, self.n, l, r)   // 闭开区间 [l, r)
    }
    pub fn add(&mut self, l: usize, r: usize, v: i64) {
        self.add_rec(1, 0, self.n, l, r, v)   // 区间加：需要懒标记
    }
}
```

## 适用条件

- 区间聚合查询 + 单点或区间修改并存
- 数据规模大且修改频繁
- 聚合函数满足结合律（求和、最值等）
- 需要在线（动态）维护

## 反例

- 只有前缀/后缀查询——树状数组更省空间、代码更少
- 数据完全静态——稀疏表 O(n log n) 预处理后 O(1) 查询更划算
- 只需要单点查询——直接数组即可
- 聚合函数不满足结合律——线段树的合并就不成立

## 并发风险

- 线段树是可变结构，不适合并发写；常见做法是每个线程一份或用锁
- 只读线段树（构建后不再修改）可安全并发查询
- 若需要"多读少写"，可用 copy-on-write 的不可变线段树（每次修改产生新根）
- 懒标记与并发修改混用时极易出错，修改路径必须独占

## 替代方案

- `algorithm.datastructure.fenwick_tree` — 只有前缀聚合时用树状数组；空间与常数都更优。
- `algorithm.datastructure.binary_heap` — 需要最值与优先队列时用堆，与区间查询无关。

## 测试说明

- 与暴力扫描（小规模）交叉比较所有区间
- 单点更新后查询结果正确
- 区间更新 + 区间查询（懒标记路径）
- 边界：整段、单个元素、空区间、越界区间
- 与树状数组的实现对比结果一致
- 随机更新序列下的不变量测试

## 实现注意

- 优先标准库/成熟库：没有标准库实现；成熟 crate 有 `segtree`、`linalg` 等，引入前需核查许可
- 复杂度：建树 O(n)，查询与更新 O(log n)，空间 O(n)（约 4n 槽位）
- 稳定性：不适用
- 内存：O(n)；`i64` 下 n = 10^6 约需 64 MB（含懒标记）
- 溢出：求和类聚合在 `i64` 下可能溢出，必要时用 `i128` 或饱和运算
- 极端输入：n = 0、n = 1、全区间更新、深度达到 log2(n) 的极端树形
- 并发安全：写操作需独占；只读版本可并发
- 限制：只支持可结合的聚合；非交换运算需谨慎处理合并顺序
