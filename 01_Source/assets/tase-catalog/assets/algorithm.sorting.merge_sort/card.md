# 归并排序（Merge Sort）

- 资产 ID：`algorithm.sorting.merge_sort`
- 类型：`algorithm`（算法）
- 分类：`sorting`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`merge_sort`、`归并排序`、`mergesort`、`归并`

## 一句话定位

稳定、最坏情况有保证的分治排序：把数组对半切开分别排好，再线性归并两个有序段。

需要一个在最坏情况下也不会退化到 O(n²) 的排序，同时还要保持相等元素的相对顺序（多关键字排序、按时间再按优先级排序）。

## 典型源文件形状

```text
merge_sort(a):
    if len(a) <= 1: return a
    mid = len(a) / 2
    left  = merge_sort(a[0..mid])
    right = merge_sort(a[mid..])
    return merge(left, right)   // 稳定地归并两个有序段

merge(left, right):
    out = new array of size len(left)+len(right)
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]: out.push(left[i++])   // <= 保证相等时先取左边（稳定）
        else: out.push(right[j++])
    out.push(remaining of left, then right)
    return out
```

## 适用条件

- 需要稳定排序（相等键的元素必须保持原有相对顺序）
- 需要最坏情况 O(n log n) 的时间保证，不接受 O(n²) 的尾部风险
- 数据能全部放进内存
- 排序的是链表等顺序访问结构（链表归并可做到 O(1) 额外空间）

## 反例

- 需要原地（O(1) 额外空间）且数据很大——归并的临时数组会成为内存瓶颈
- 数据量小——插入排序或标准库的排序更快（标准库会按长度切换算法）
- 只需要部分排序结果（如前 k 个）——完全排序是浪费
- 追求极致常数性能且不要求稳定——标准库的 pdqsort 更快

## 并发风险

- 归并的左右两半互不依赖，天然可并行（分治并行），但线程调度开销通常大于收益
- 归并本身不共享状态，多个排序任务并行时各自持有缓冲区即可
- 若把归并排序实现为并行归并树，需要注意中间缓冲的内存峰值是 O(n) × 线程数级别
- 排序只操作独占的切片时最安全；共享切片上的排序需要外部同步

## 替代方案

- `algorithm.sorting.heap_sort` — 需要 O(1) 额外空间且不要求稳定时，堆排序是归并的替代。
- `algorithm.sorting.quick_sort` — 原地、常数小、平均更快，但最坏 O(n²)。
- `algorithm.sorting.radix_sort` — 键是整数且范围可控时，基数排序可以更快。

## 测试说明

- 随机输入与标准库 `sort` 交叉比较，断言结果完全一致
- 全部相等、全部递增、全部递减、逆序、含大量重复值
- 空数组、单元素、两个元素（边界）
- 稳定性测试：用 (key, index) 对排序，断言相等 key 的 index 保持递增
- 性质测试：断言输出是输入的一个排列（长度一致、元素集合一致）

## 实现注意

- 优先标准库：Rust 的 `slice::sort`（稳定）与 `sort_unstable` 已高度优化，本卡用于教学与理解，不要在生产中手写
- 复杂度：时间 O(n log n) 最坏/平均/最好，额外空间 O(n)
- 稳定性：稳定；相等元素保持原相对顺序（`merge` 中用 `<=` 而非 `<`）
- 内存：需要与输入等长的辅助数组，内存受限时应改用原地算法或分块归并
- 溢出：`mid = len/2` 而非 `(lo+hi)/2`，避免下标相加溢出；长度用 `usize` 时 `lo+hi` 可能溢出
- 极端输入：已排序输入不会更快（仍是 O(n log n)），但拷贝量与递归深度会变化
- 并发安全：算法本身无共享状态，多线程各自排序不同切片是安全的；同一数据并发排序需要外部同步
- 限制：需要把整个序列载入内存；外部排序（磁盘）需要另做归并趟数与归并路径设计
