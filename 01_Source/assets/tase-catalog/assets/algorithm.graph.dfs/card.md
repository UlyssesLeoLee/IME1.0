# 深度优先搜索（Depth-First Search）

- 资产 ID：`algorithm.graph.dfs`
- 类型：`algorithm`（算法）
- 分类：`graph`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`dfs`、`深度优先搜索`、`depth first search`

## 一句话定位

一条路走到黑，走不通就退回上一个岔口，把整棵可达子图走遍。

判断图里有没有环、统计连通块、枚举所有满足约束的组合（回溯），都需要这种"深入并回退"的遍历方式。

## 典型源文件形状

```rust
pub fn dfs<F: FnMut(usize)>(&self, start: usize, mut visit: F) {
    let mut visited = vec![false; self.n];
    let mut stack = vec![start];
    while let Some(v) = stack.pop() {
        if visited[v] { continue; }
        visited[v] = true;
        visit(v);
        for &u in &self.adj[v] {
            if !visited[u] { stack.push(u); }
        }
    }
}
```

## 适用条件

- 检测环（DFS 带递归栈判定）
- 统计连通分量
- 拓扑排序（DFS 后序逆序）
- 回溯搜索（组合、排列、约束满足）
- 桥与割点、拓扑结构分析

## 反例

- 需要无权图最短路径——用 BFS
- 只需要连通性与合并——并查集更省空间
- 图是 DAG 且只需排序——拓扑排序现成
- 状态空间巨大且剪枝困难——回溯会指数爆炸

## 并发风险

- DFS 的回溯语义本质是串行的，并行化困难（不同分支可并行，但需要同步共享状态）
- 并行 DFS 常见做法是"随机化起点 + 多次独立 DFS"来近似采样，不是精确算法
- 访问标记若被多线程共享需要原子操作；更好的做法是每个线程一份标记
- 回溯搜索中的共享剪枝结构（如记忆化表）需要同步，通常用每线程一份或加锁

## 替代方案

- `algorithm.graph.bfs` — 需要最短路径或按层遍历时用 BFS。
- `algorithm.graph.topological_sort` — DAG 上要线性顺序时直接用拓扑排序。

## 测试说明

- 断言每个节点恰好被访问一次
- 环检测：有环与无环的图各一组
- 连通分量数量断言
- 深链图（如 100000 个节点的链）断言不栈溢出（用显式栈实现）
- 自环、双向边（无向图里是同一个环）

## 实现注意

- 优先标准库/成熟库：`petgraph` 提供 DFS/BFS 与图类型，引入前需核查许可与维护状况
- 复杂度：时间 O(V + E)，额外空间 O(V)（访问标记 + 栈）
- 稳定性：不适用
- 内存：显式栈最坏 O(V)；递归实现隐式占用调用栈
- 溢出：递归深度等于图深度，Rust 默认线程栈 2 MiB，深链图会栈溢出——用显式栈或增大栈
- 极端输入：完全图、极深链、大量孤立点
- 并发安全：只读图上的独立 DFS 线程安全；共享访问标记需要原子或分片
- 限制：递归版有栈深限制；回溯类应用最坏是指数复杂度
