# 模幂运算（Modular Exponentiation）

- 资产 ID：`algorithm.math.modular_exponentiation`
- 类型：`algorithm`（算法）
- 分类：`math`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`modular_exponentiation`、`模幂`、`模快速幂`、`pow mod`

## 一句话定位

快速幂的模运算版本：每步乘法后立刻取模，把数值大小始终控制在 m 以内。

计算 (123456789)^(10^18) mod 1000000007，精确幂会溢出，取模才能让中间值可控。

## 典型源文件形状

```rust
pub fn pow_mod(base: u64, exp: u64, m: u64) -> u64 {
    assert!(m > 0);
    let mut result = 1u64 % m;
    let mut b = base % m;
    let mut e = exp;
    while e > 0 {
        if e & 1 == 1 { result = mul_mod(result, b, m); }
        b = mul_mod(b, b, m);
        e >>= 1;
    }
    result
}
```

## 适用条件

- 大数幂运算的取模计算（RSA、哈希校验、组合数模质数）
- 模数为质数且指数巨大时的快速计算
- 需要把乘法控制在模数范围内以避免溢出
- 作为其它数论算法的子步骤

## 反例

- 不需要取模且指数小——直接乘法即可
- 模数不是质数且需要费马小定理化简——该定理要求质数，误用会得到错误结果
- 需要计算模逆元——用扩展欧几里得算法
- 模数极大（超过 128 位）——需要大整数库

## 并发风险

- 纯函数、无共享状态，天然线程安全
- 大整数模乘库通常内部有可变缓冲区，跨线程要各自实例
- 密码学场景下的实现必须使用经过审查的库（见实现注意），不要自写
- 批量计算时可在数据分片上并行，各自独立

## 替代方案

- `algorithm.math.fast_power` — 不带取模的精确幂，注意中间值溢出。
- `algorithm.math.extended_euclidean` — 需要模逆元或贝祖系数时用扩展欧几里得。

## 测试说明

- 与朴素连乘取模（小指数）交叉比较
- 指数 0（结果为 1 mod m）、底数为 0
- m = 1（所有结果为 0）、m 为质数与合数各一组
- 大指数（如 2^64-1）
- 性质测试：断言 pow_mod(b, e, m) 与朴素结果在可验证范围内一致
- 互质性测试：断言 pow_mod(b, m-1, m) == 1（m 为质数且 b 与 m 互质）

## 实现注意

- 优先标准库/成熟库：Rust 标准库没有模幂；成熟 crate 有 `num-bigint`（模幂）、`crypto-bigint` 等，引入前需核查许可
- 复杂度：时间 O(log e) 次模乘，空间 O(1)
- 稳定性：不适用
- 内存：常数（定长类型）；大整数则与位数成正比
- 溢出：mul_mod 里 `a * b` 在 u64 下会溢出——必须用 u128 中转或用 `overflowing_mul` + 规约，这是最常见的 bug
- 极端输入：m = 1、exp = 0、底数为 0、m 接近 u64::MAX
- 并发安全：纯函数；大整数库实例不可跨线程共享
- 限制：定长整数下模数受类型宽度限制；密码学用途必须使用经过审查的库
