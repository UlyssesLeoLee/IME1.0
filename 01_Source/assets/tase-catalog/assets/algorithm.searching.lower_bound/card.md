# 下界查找（Lower Bound）

- 资产 ID：`algorithm.searching.lower_bound`
- 类型：`algorithm`（算法）
- 分类：`searching`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`lower_bound`、`下界`、`partition_point`、`第一个大于等于`

## 一句话定位

二分查找的变体：不要求命中，返回"第一个 ≥ x 的下标"，没有则返回序列长度。

要往有序数组里插入元素又不破坏顺序，需要知道插入位置；有重复元素时还要区分"插在最前"还是"插在最后"。

## 典型源文件形状

```rust
pub fn lower_bound<T: Ord>(a: &[T], x: &T) -> usize {
    let mut lo = 0usize;
    let mut hi = a.len();
    while lo < hi {
        let mid = lo + (hi - lo) / 2;
        if a[mid] < x { lo = mid + 1 } else { hi = mid }
    }
    lo                            // 第一个 >= x 的位置
}
```

## 适用条件

- 需要把元素插入有序序列且保持有序
- 需要"第一个满足谓词的位置"（谓词需单调）
- 需要统计某个值的出现次数（配合 upper_bound）
- 需要按阈值切分有序数据

## 反例

- 只需要存在性判断——binary_search 更直接
- 序列无序——前提不满足
- 谓词非单调（例如"偶数位置"）——二分的前提失效
- 数据量小——线性扫描找插入位置更简单

## 并发风险

- 只读操作，共享不可变切片是并发安全的
- 要求底层序列在查找期间不被修改，否则结果没有意义
- 二分 + 插入的组合不是原子的：并发插入会破坏有序性，需要锁或更高层的并发结构
- 在分片读写的存储上做 lower_bound 只能保证分片内有序，全局有序需额外机制

## 替代方案

- `algorithm.searching.upper_bound` — upper_bound 返回第一个 > x 的位置，两个一起用可定位等价区间。
- `algorithm.searching.binary_search` — 只需要命中位置时用 binary_search。

## 测试说明

- 与线性实现交叉比较，断言位置一致
- x 小于所有元素（返回 0）、大于所有元素（返回 len）
- 空数组（返回 0）
- 有重复元素时断言返回最左的那个位置
- 用谓词版本（如第一个长度 ≥ 5 的元素）测试单调性假设被破坏时的行为

## 实现注意

- 优先标准库：Rust 的 `slice::partition_point` 就是 lower_bound（要求谓词单调）
- 复杂度：时间 O(log n)，额外空间 O(1)
- 稳定性：不适用
- 内存：O(1)
- 溢出：中点用 `lo + (hi - lo) / 2`
- 极端输入：空数组与边界值必须安全；全等元素时返回 0
- 并发安全：只读安全，但前提是数据不变
- 限制：要求有序或谓词单调；不适用于无序数据
