# 双指针（Two Pointers）

- 资产 ID：`algorithm.searching.two_pointers`
- 类型：`algorithm`（算法）
- 分类：`searching`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`two_pointers`、`双指针`、`对撞指针`、`双指针法`

## 一句话定位

让两个指针按单调方向各走一遍数组，用 O(n) 而不是 O(n log n) 或 O(n²) 解决配对问题。

有序数组里找两数之和，双重循环要 O(n²)；哈希表要额外 O(n) 空间；双指针一次扫描就够。

## 典型源文件形状

```rust
pub fn two_sum_sorted(a: &[i64], target: i64) -> Option<(usize, usize)> {
    let mut lo = 0usize;
    let mut hi = a.len();
    while lo < hi {
        let sum = a[lo] + a[hi - 1];
        if sum == target { return Some((lo, hi - 1)); }
        if sum < target { lo += 1 } else { hi -= 1 }
    }
    None
}
```

## 适用条件

- 有序数组上的两数之和、配对、分割问题
- 回文判断（对撞指针）
- 需要 O(1) 额外空间的线性扫描
- 问题具有"移动某个指针不会错过解"的单调性

## 反例

- 数组无序——对撞指针失效（可先排序，但会丢失原索引）
- 需要返回所有配对且数量多——哈希表或排序后枚举更方便
- 数据流式到达且无法回看——双指针需要随机访问
- 指针移动不具单调性——移动策略必须能被证明不漏解

## 并发风险

- 只读扫描，共享不可变切片是并发安全的
- 若两个指针分别由两个线程推进（生产-消费式），需要保证中间状态可见性与内存序
- 对同一可变数组并发做双指针扫描是不安全的，需要快照或独占访问
- 算法本身是 O(n) 的只读过程，无需锁

## 替代方案

- `algorithm.searching.sliding_window` — 窗口大小固定或可变、且条件是"区间内满足某性质"时用滑动窗口。
- `algorithm.datastructure.hash_table` — 无序数据或需要多次查询时，哈希表更通用（代价是 O(n) 空间）。

## 测试说明

- 与暴力解法（小规模）交叉比较，断言结果一致
- 无解、全解、唯一解、多解（取约定的首个）
- 空数组、单元素、两个元素
- 含负数、含 0、含重复值
- 断言指针移动次数上界（每个指针最多走 n 步）

## 实现注意

- 优先标准库/成熟库：能用标准库迭代器组合表达的，优先用迭代器；但双指针的原地扫描仍需手写
- 复杂度：时间 O(n)（每个指针最多走 n 步），额外空间 O(1)
- 稳定性：不适用
- 内存：O(1)，不需要辅助结构
- 溢出：求和/差值可能溢出整数范围（如 i32 相加），需要时改用 i64 或检查溢出
- 极端输入：全相同元素时指针仍单调推进；空输入要安全返回
- 并发安全：只读安全，前提是数组在扫描期间不变
- 限制：依赖有序性与单调移动策略的正确性证明；不适用于无序或流式单遍数据
