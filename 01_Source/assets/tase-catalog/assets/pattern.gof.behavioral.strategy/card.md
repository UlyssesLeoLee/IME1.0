# 策略（Strategy）

- 资产 ID：`pattern.gof.behavioral.strategy`
- 类型：`pattern`（设计模式）
- 分类：`behavioral`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`Strategy`、`策略模式`、`strategy pattern`

## 一句话定位

把"怎么做"抽成同族可互换的策略对象，让调用方在运行期挑一个，而不必写一串类型分支。

同一段流程需要支持多种打分/排序/压缩算法，每加一种就把 `match` 加长一分，且分支散落在流程中间。

## 典型源文件形状

```rust
pub trait Pricing {
    fn price(&self, base: f64, qty: u32) -> f64;
}

pub struct VolumeDiscount;
impl Pricing for VolumeDiscount {
    fn price(&self, base: f64, qty: u32) -> f64 {
        let factor = match qty { 0..=9 => 1.0, 10..=99 => 0.9, _ => 0.8 };
        base * f64::from(qty) * factor
    }
}

pub fn quote(p: &dyn Pricing, base: f64, qty: u32) -> f64 { p.price(base, qty) }
```

## 适用条件

- 同一流程需要多种算法，且选择依据在运行期才确定
- 算法族有共同契约，调用方只依赖契约
- 算法会持续新增，且不希望改动主流程
- 希望算法可以独立测试、独立替换（如注入假实现）

## 反例

- 算法只有一个——不要为"未来也许会变"提前抽象
- 算法差异用几个参数就能表达——参数比策略对象更简单
- 调用方需要在多个算法之间做复杂决策——决策本身应该单独抽成一个策略或规则
- 策略数量固定且都很短——一个 `enum` + `match` 常常更好，还能穷尽检查

## 并发风险

- 策略实现应尽量无状态：无状态策略可自由跨线程共享
- 有状态策略（带缓存、计数器）必须自己同步，或明确标记为不可共享并用 `&mut` 传参
- 策略对象被 `Box<dyn Trait>` 持有时默认不 `Send`/`Sync`，跨线程需加约束
- 在运行期热切换策略时，切换点要有明确同步语义，否则可能执行到一半换策略

## 替代方案

- `pattern.gof.behavioral.state` — 状态模式下行为随对象状态变化；策略模式下对象状态不变、只是算法不同。
- `pattern.gof.structural.bridge` — 桥接是"两个维度都独立变化"的组合，策略是"一个维度可替换"。

## 测试说明

- 对每个策略写独立用例，断言同一输入下的结果
- 写契约测试：所有策略对同一组输入都必须满足不变量（如价格非负）
- 测试运行期切换策略：切换前后行为符合预期，且没有半切换状态
- 不要在测试里依赖策略的实现细节，只断言契约

## 实现注意

- Rust 中策略常写成 trait + 泛型（静态派发、零开销）或 `dyn`（动态派发、运行期切换）
- 闭包也是策略：简单的一两个行为差异时，传入闭包比定义 trait 更轻
- 策略对象不应访问全局可变状态，否则策略就不再可替换
- 策略与"配置"要分清：能用数据（参数、配置表）表达的，不要用策略对象
