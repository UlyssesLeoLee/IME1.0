# Kruskal 最小生成树（Kruskal’s Minimum Spanning Tree）

- 资产 ID：`algorithm.graph.kruskal`
- 类型：`algorithm`（算法）
- 分类：`graph`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`Kruskal`、`最小生成树`、`MST`、`克鲁斯卡尔算法`

## 一句话定位

把边按权重从小到大看，只要不形成环就收进树里，用并查集快速判断"是否已连通"。

布线最省成本、聚类里的最小生成树、路由的骨干链路——本质都是"用最便宜的边把所有点连起来"。

## 典型源文件形状

```text
kruskal(graph):
    sort all edges by weight ascending
    dsu = DisjointSetUnion(V)
    tree = []
    for (u, v, w) in edges:
        if dsu.find(u) != dsu.find(v):
            dsu.union(u, v)
            tree.push((u, v, w))
            if len(tree) == V - 1: break
    if len(tree) != V - 1: raise NotConnectedError
    return tree
```

## 适用条件

- 无向带权图上求最小生成树
- 图稀疏（E 接近 V）时比 Prim 更合适
- 边可以整体排序（内存放得下）
- 网络设计、布线、聚类、图像分割

## 反例

- 图是有向的——最小生成树无定义
- 图稠密（E ≈ V²）——Prim 的 O(V²) 邻接矩阵实现可能更省内存
- 需要带权图的最大生成树——把权重取反即可，但要注意浮点取反的精度
- 图不连通——Kruskal 只能得到生成森林，需求应说明

## 并发风险

- Kruskal 的排序阶段可并行；加边阶段必须串行或用并发安全的并查集
- 并查集本身用路径压缩 + 按秩合并时几乎是并发的，但"检查 + 合并"两步要原子
- 并行 Kruskal 的常见做法是先按边分成多个子集并行求局部 MST，再用 Borůvka 式合并
- 只读图上的排序阶段完全并行安全

## 替代方案

- `algorithm.graph.prim` — 稠密图或需要边集较小时用 Prim，它从点出发逐步扩张。
- `algorithm.graph.union_find` — 并查集是 Kruskal 的核心工具，也是它的独立资产。

## 测试说明

- 断言树有 V-1 条边且所有顶点连通
- 断言树的总权重等于参考实现（如 Prim）的结果
- 不连通图：断言明确报错或返回生成森林
- 含平行边与自环：断言自环被跳过、平行边正确取舍
- 权重相等时的确定性：断言相同输入产生相同结果（排序稳定或按 tie-break）

## 实现注意

- 优先标准库/成熟库：`petgraph` 提供 Kruskal/Prim，引入前需核查许可
- 复杂度：时间 O(E log E)（排序主导），额外空间 O(V + E)
- 稳定性：不适用（结果是一棵树）
- 内存：需要存下所有边并排序，O(E)
- 溢出：权重与总权重之和要用足够宽的类型（`u64` 或 `i128`），累加总权重时尤其注意
- 极端输入：单节点、两点一边、平行边、自环、完全图、不连通图
- 并发安全：排序可并行，加边需串行或用并发并查集
- 限制：只适用于无向图；最小生成树不等于最短路径树，两者常被混淆
