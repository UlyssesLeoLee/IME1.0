# 快速选择（Quickselect）

- 资产 ID：`algorithm.sorting.quickselect`
- 类型：`algorithm`（算法）
- 分类：`sorting`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`quickselect`、`快速选择`、`nth_element`、`第 k 大`

## 一句话定位

用与快排相同的分区思想，但只递归处理包含目标的一侧，从而把求第 k 小的代价降到平均 O(n)。

只关心中位数、前 10% 或某个分位数，却为此排了整个数组，浪费了一个数量级的时间。

## 典型源文件形状

```text
quickselect(a, k):                   // 第 k 小（0 基）
    lo = 0; hi = len(a)-1
    while lo < hi:
        p = partition(a, lo, hi)
        if p == k: return a[p]
        else if p < k: lo = p+1
        else: hi = p-1
    return a[k]
```

## 适用条件

- 只需要顺序统计量（中位数、分位数、第 k 大）
- 数据量大而排序代价过高
- 不要求完整有序，只要求目标元素的正确位置
- 可接受平均时间保证（配合随机枢轴）

## 反例

- 需要全部元素有序——完整排序更合适
- 只需要最大值或最小值——一趟扫描 O(n) 更简单
- 需要前 k 个全部有序——用堆或部分排序
- 数据量小——排序的常数更小，差别不大

## 并发风险

- 原地分区，非并发安全的共享操作
- 随机枢轴的生成若使用共享的全局 RNG，需要保证线程安全（`rand::thread_rng` 是线程本地且安全的）
- 分区只处理包含目标的一侧，无法像快排那样直接并行
- 若外层对多个分位数反复调用 quickselect，重复的分区工作是浪费

## 替代方案

- `algorithm.sorting.top_k_heap` — 需要前 k 个元素（而不只是第 k 个）时用小顶堆更合适。
- `algorithm.datastructure.binary_heap` — 若数据是流式的或需要多次查询分位数，堆/有序结构比反复 quickselect 更合适。

## 测试说明

- 与"完整排序后取第 k"交叉比较，断言结果一致
- k = 0、k = n-1、k 为中间值的边界
- 空数组与单元素（应明确返回错误而不是 panic）
- 全部相等、含大量重复值
- 多次随机枢轴运行，结果必须稳定一致

## 实现注意

- 优先标准库：Rust 的 `slice::select_nth_unstable`（自 1.49 起）就是 quickselect 的实现，不要手写
- 复杂度：平均 O(n)，最坏 O(n²)，额外空间 O(1)（迭代写法）
- 稳定性：不适用（只返回单个元素）
- 内存：原地，几乎不额外分配
- 溢出：k 的边界要显式检查（`k >= n` 越界）
- 极端输入：大量重复值时三路分区可避免退化；已排序输入配合随机枢轴无问题
- 并发安全：原地修改，单线程独占
- 限制：结果不保证整体有序；若需要多次分位数查询，反复调用会重复工作
