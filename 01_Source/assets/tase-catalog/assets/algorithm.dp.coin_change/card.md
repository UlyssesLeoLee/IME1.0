# 找零（硬币兑换）（Coin Change）

- 资产 ID：`algorithm.dp.coin_change`
- 类型：`algorithm`（算法）
- 分类：`dp`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`coin_change`、`找零`、`硬币兑换`、`最少硬币数`

## 一句话定位

完全背包：金额从小到大遍历，对每个金额尝试所有面额，更新最少硬币数。

收银找零、凑整支付、资源分配的最少步骤数，都是"无限供应的物品凑出目标值"。

## 典型源文件形状

```text
coin_change_min(coins, amount):
    INF = amount + 1
    dp = array of size amount+1 filled with INF
    dp[0] = 0
    for a in 1..=amount:
        for c in coins:
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1
    return dp[amount] if dp[amount] != INF else unreachable
```

## 适用条件

- 每种面额可无限次使用
- 金额是整数且规模可控
- 需要最少数量或可达性判定
- 与 0-1 背包同构（把"价值"固定为 1）

## 反例

- 每种面额只能用一次——用 0-1 背包
- 金额极大——改用数论方法（如面额为 2/3 的闭式解）或按最大公约数缩放
- 需要最少硬币的具体方案——DP 只给数量，需记录前驱
- 面额是实数或任意代币——整数 DP 不适用

## 并发风险

- DP 纯计算，无共享状态
- 并行化需按金额分块并处理块间依赖（金额 a 依赖更小的金额），较难；一般不并行
- 只读面额表在多线程下共享安全
- 若把结果缓存进全局哈希表，更新需要同步

## 替代方案

- `algorithm.dp.knapsack_01` — 物品只能用一次时用 0-1 背包。
- `algorithm.datastructure.binary_heap` — 若需要枚举所有可能方案而不是最优值，堆更适合做搜索。

## 测试说明

- 与暴力枚举（小金额）交叉比较
- 金额为 0（答案 0）、面额大于金额（不可达）
- 有零面额（必须过滤，否则死循环/无穷小）
- 重复面额（应去重）
- 面额有最大公约数 > 1 时，较大的不可达金额要正确判定
- 贪心会失败的例子（如面额 1,3,4，金额 6）

## 实现注意

- 优先标准库/成熟库：没有标准库实现；成熟 crate 有 `change-making` 等，引入前需核查许可
- 复杂度：时间 O(amount × coins)，额外空间 O(amount)
- 稳定性：不适用
- 内存：O(amount)；amount = 10^7 时每项 4 字节约 40 MB，需评估
- 溢出：`dp[a - c] + 1` 在 INF 哨兵上要避免溢出，INF 取 `amount + 1` 可避免
- 极端输入：amount = 0、无解、零面额、重复面额、面额数量很大
- 并发安全：纯计算，通常不并行
- 限制：伪多项式复杂度；要求整数金额；不给出具体方案
