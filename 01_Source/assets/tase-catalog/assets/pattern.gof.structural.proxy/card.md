# 代理（Proxy）

- 资产 ID：`pattern.gof.structural.proxy`
- 类型：`pattern`（设计模式）
- 分类：`structural`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`Proxy`、`代理模式`、`proxy pattern`

## 一句话定位

用替身挡住真实对象，让"访问它"这件事可以被延迟、被授权、被改写成本地或远程。

远程对象、懒加载的大资源、需要权限校验的敏感对象，直接持有真实实例会让创建时机、权限边界和失败处理都散落在调用点。

## 典型源文件形状

```rust
pub trait Document { fn read(&self) -> &str; }

pub struct LazyDocument { path: String, cache: Option<String> }

impl Document for LazyDocument {
    fn read(&self) -> &str {
        // 需要可变缓存时用 RefCell / Mutex，或改为一次性加载的 OnceCell
        self.cache.as_deref().unwrap_or("")
    }
}
```

## 适用条件

- 目标对象创建代价高或可能不存在，需要惰性创建
- 目标是远程资源，代理负责序列化、寻址与重试
- 需要在访问点做权限检查、审计或限流
- 需要为一个受限接口提供本地替身（测试、离线模式）

## 反例

- 目标是本地廉价对象——直接用即可
- 代理里开始写业务判断——应把业务逻辑放回领域层，代理只管"访问控制"
- 代理与目标的接口语义并不完全一致（代理要转换参数/返回值）——那是适配器
- 只是为了加日志而套代理——装饰器更贴切

## 并发风险

- 惰性初始化必须用 `OnceCell`/`OnceLock`/`Mutex` 保护，裸 `Option` + `&mut self` 不是线程安全的
- 远程代理的并发请求要考虑连接复用与背压，不能每个调用新建连接
- 访问控制的检查必须在代理里做，不能依赖调用方自觉，否则绕过代理就失去防线
- 代理内部若缓存结果，要说明一致性语义（强一致/最终一致/不缓存）
- 远程代理的失败要区分"目标不可达"与"业务拒绝"，前者通常可重试，后者不可

## 替代方案

- `pattern.gof.structural.decorator` — 装饰器保持语义不变地叠加行为，代理改变访问方式（惰性/远程/权限），两者常混淆。
- `pattern.gof.structural.adapter` — 适配器用于接口不兼容的转换，代理用于接口相同但访问方式不同的场景。

## 测试说明

- 用假目标（fake target）测试代理的转发是否正确、参数是否原样传递
- 测试惰性语义：目标在第一次访问前不应被创建（用计数器断言）
- 测试访问控制：未授权访问必须被拒绝且不触达目标
- 远程代理要测超时、重试与错误分类；不要在单测里依赖真实网络

## 实现注意

- 代理与装饰器结构相似，判据是"是否改变访问语义"
- 在 Rust 中代理通常实现同一 trait 并持有 `Option<T>`/`Box<dyn Trait>`；注意对象安全
- 远程代理的协议与重试策略应可配置，不要硬编码
- 代理链（多层代理）会让排障困难，保留一条无代理的直连路径仅用于诊断
