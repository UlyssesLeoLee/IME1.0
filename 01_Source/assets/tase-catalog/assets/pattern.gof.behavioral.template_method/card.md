# 模板方法（Template Method）

- 资产 ID：`pattern.gof.behavioral.template_method`
- 类型：`pattern`（设计模式）
- 分类：`behavioral`
- 版本：`1.0.0`
- 状态：`DOCUMENTED`（知识卡已成文，尚未经人工审阅；本资产没有任何已认证的语言实现）
- 别名：`TemplateMethod`、`模板方法模式`、`template method`

## 一句话定位

把"算法流程"固定下来，把其中会变的几个步骤做成可覆写的钩子，让子类只填差异。

多个类里有几乎相同的导入-解析-校验-落库流程，只是解析那一步不同，复制粘贴后改流程要改 N 个地方。

## 典型源文件形状

```rust
pub struct Importer {
    pub fn run(&self) -> Result<u32, String> {
        let raw = self.fetch()?;
        let rows = self.parse(&raw)?;
        self.persist(&rows)
    }
    fn fetch(&self) -> Result<String, String> { /* 子类覆写 */ }
    fn parse(&self, raw: &str) -> Result<Vec<u32>, String> { /* 子类覆写 */ }
    fn persist(&self, rows: &[u32]) -> Result<u32, String> { Ok(rows.len() as u32) }
}
```

## 适用条件

- 多个类型共享同一套流程骨架，只在若干步骤上不同
- 流程顺序与钩子调用点必须保持稳定
- 希望"忘记调用某个步骤"在编译期或结构上不可能发生
- 变体数量有限且已知

## 反例

- 骨架只有两三步——把步骤做成参数（函数/闭包）比继承更直接
- 变体之间连流程顺序都不同——继承无法表达，应该各自独立实现或用策略组合
- 需要运行期切换骨架——模板方法是编译期固定的，应改用策略
- 用继承模拟模板方法时注意 Rust 没有类继承，通常用 trait 默认方法或组合实现

## 并发风险

- 模板方法若通过 `&mut self` 修改共享状态，多线程调用需要外部同步
- 钩子实现若阻塞，会占住外层锁；模板方法本身不提供并发语义
- 钩子里若调用父类骨架其它步骤，可能重入导致状态不一致，应在文档中禁止
- 共享状态优先通过参数传入，而不是放进模板对象字段

## 替代方案

- `pattern.gof.behavioral.strategy` — 变体数量多或需要运行期选择时用策略；变体少且骨架固定时模板方法更省代码。
- `pattern.gof.structural.adapter` — 若差异只是"输入输出格式不同"，适配器比继承骨架更合适。

## 测试说明

- 测每个子类实现的钩子，断言骨架调用顺序固定（可用记录型假实现）
- 断言钩子抛错时骨架的错误传播符合预期（后续步骤不执行）
- 断言默认钩子实现给出了合理的默认行为
- 测试同一骨架被多个子类共享时的隔离性（一个子类出错不影响另一个）

## 实现注意

- Rust 里没有类继承，模板方法通常用 trait 默认方法 + 结构体组合实现，不要硬造继承链
- 钩子的数量要少：超过三四个钩子，调用方就需要理解全部组合，模板的价值下降
- 骨架里不要做"可选步骤"的大量布尔开关，可用钩子的默认实现表达
- 模板方法与依赖注入结合：把可变的外部依赖也做成参数，而不是继承钩子
